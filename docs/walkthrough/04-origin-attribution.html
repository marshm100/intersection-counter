4. Origin & Attribution

Every track needs an origin leg before its movement can be counted. The current pipeline does this by matching the whole trajectory against the path bank and reading the origin off the path it fits — a more robust signal than the point-and-angle tiers it replaced.

What changed. The old pipeline assigned origin from three geometric tiers (tripwire → backward-extrapolation → heading). Backward-extrapolation was added 2026-05-20 and removed after measurement: projecting a track backward to a frame edge baked in an edge-leg bias and didn't generalize. It's been superseded by path-bank matching. The early tiers still run — but now mostly as a gate for "is this even an intersection vehicle," with the joint scorer making the real call at finalization.

The joint partial-Fréchet scorer

When a track is finalized and the camera has a bank, score_path_joint compares the track against every path and returns the best match. Origin, destination, and movement are then all read off the winning path — none is estimated from the track's own (unreliable) entry tangent.

The key idea is partial matching. A vehicle first detected mid-turn only traces a suffix of its road's polyline; the approach portion was never seen. So we score the track against the best-aligning sub-curve of each path, and the uncovered approach doesn't count against the match.

How the match is scored

The cost between a track and a path sub-curve is a mean coupled distance (DTW-aligned), in pixels — not classic Fréchet. Fréchet is a sup norm that a single jittery tracking point spikes (best-match Fréchet ran ~82 px median on real tracks); the mean coupled distance runs ~29 px, the scale the geometry actually lives at. A match must clear several bars:

A stricter bar for turns

A straight through-trajectory can shape-match the early sub-curve of a turn polyline and get mislabeled as a turn. So turn paths (left/right/u-turn) face an extra gate: a turn may claim a track only if the track's tail aligns with the turn's exit tangent (tail_prior ≥ 0.85) and it covers enough of the turn arc (coverage ≥ 0.40). A through goes straight, so its tail never aligns with a turn's exit — it's spared.

The origin-rewrite gate (snap-magnet defense)

Reading origin off the matched path is powerful but dangerous: a straight "turn" polyline can capture a through track and rewrite its origin to a leg that vehicle never entered from. The worst case measured: a cam4 EB-left path with manual volume 6 attributed 214 events by swallowing the arterial.

The gate: reject a TURN match that would rewrite origin to a leg that is not the nearest origin-anchor to the track's first point — but only when the trajectory is itself geometrically straight (straightness ≥ 0.97). Real turns curve, so a genuine mid-turn entry (the whole reason the joint scorer exists) stays below the straightness floor and is spared. Self-limiting, data-driven, no per-camera flag. Result on replay: cam4 22.7% → 7.0% net, other cameras unharmed.
