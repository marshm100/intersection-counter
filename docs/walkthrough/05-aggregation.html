5. Aggregation

The DB now holds one row per detected vehicle pass. Export rolls those rows up into the TMC Excel format that traffic engineers actually consume — 15-minute intervals, per leg, per movement type, with hard-coded integers (no formulas).

From per-event rows to per-bucket counts

What the Excel file contains

backend/services/excel_export.py emits a workbook with three sheets, all integers, no formulas (PRD constraint):

Sheet 1 — TMC Summary

Totals over the entire processed window. One row per leg, columns for each movement type plus a row total. The high-level "how many vehicles turned each way" answer.

(Numbers shown are from the 2026-05-12 baseline Balanced run, 23.3 min of 7 AM peak.)

Sheet 2 — Time Series

One row per 15-min bucket, total vehicles in that bucket. Used by traffic engineers to see peaks-within-peaks (the 7:30 surge vs the 7:00 trickle). Movement-level breakdowns aren't exploded here — Sheet 3 has the per-event detail.

Sheet 3 — Raw Events

Every vehicle_events row: timestamp, origin leg, movement, vehicle class, confidence, frame number, manual-edit flag. Used for QA — spotting outliers, sampling for visual verification, debugging misclassifications.

Cross-camera dedup

When an intersection-day has multiple cameras with overlapping coverage, the v3 aggregator collapses parallel-overlap duplicates before counting. Two vehicle events from different cameras that fall in the same time window and the same (origin, movement) bucket within a tolerance are treated as the same physical vehicle.

Trim filtering

Trims are wall-clock windows scoped to the intersection-day (e.g., "process 7:00–9:00 AM and 4:00–6:00 PM, skip the rest"). Events whose timestamp_video falls outside any active trim are excluded from the aggregation. The raw events are kept in the DB — just not exported.

What "manual override" looks like

Engineers can review individual events in the dashboard and reject or re-label them. Rejection sets rejected=1 and the row is excluded from aggregation. Re-labeling sets manually_edited=1 and the new movement label takes effect. Both states are exported in Sheet 3 so the audit trail is preserved.

Validating the count

scripts/groundtruth.py compares the live vehicle_events to a manual TMC CSV from a prior commercial study. The 2026-05-12 baseline snapshot is saved as evaluations/baseline.json. Run py scripts/groundtruth.py --diff baseline after any accuracy change to see which legs gained or lost recall.

Done. That's the full pipeline. The interesting parts to keep iterating on are origin assignment (Bug A — the backward-extrapolation fix needs live validation) and classification (Bug B — derive_movement assumes peer roads; needs to handle terminating side streets).
