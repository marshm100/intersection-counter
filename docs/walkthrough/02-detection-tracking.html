2. Detection & Tracking

Each frame is run through YOLO to find vehicle bounding boxes; the detections are cached so the rest of the pipeline can be re-run without re-detecting. A tracker — ByteTrack or BoT-SORT, chosen per camera — stitches same-vehicle detections across frames into a track that accumulates a trajectory (the list of bbox centers over time).

Per-frame data flow

What tracking looks like over time

Across frames, association turns per-frame boxes into one moving identity with a growing trail. When two vehicles pass through near-occlusion, that identity can jump — the failure mode the tracker choice (and the path bank downstream) has to survive.

YOLO detection

Model is configurable per processing mode. Vehicle classes (COCO): 2 car, 3 motorcycle, 5 bus, 7 truck. Pedestrians intentionally excluded — out of scope for v2.

Confidence threshold is intentionally low (0.08–0.15 depending on mode). At 1080p with the large model, partially-backlit vehicles can return at conf 0.10–0.14; raising the floor would silently drop them.

The detection cache — detect once, retrack many

Detection is by far the slowest stage. So every frame's detections are written to a per-camera Parquet cache (balanced_960_skip1.parquet), keyed by a content hash of the video. Anything downstream — a different tracker, a new bank, a tweaked attribution rule — replays against the cache in minutes instead of re-running YOLO for hours. This is what makes the accuracy iteration loop (page 7) practical: apply_bank.py and apply_hybrid.py "retrack" cached detections, never re-detecting.

Class-agnostic NMS (optional, pre-track). On a high-frame-rate camera the same vehicle is sometimes double-boxed, which inflates counts downstream. A strict non-max-suppression pass before tracking (PRE_TRACK_NMS_IOU, 0.85 on cam2) collapses the duplicates. It ships default-off and is enabled per camera — on lower-fps cameras it over-merges genuinely separate vehicles. (cam2, at 25 fps, is the one that needs it — see page 7.)

ByteTrack association

Each new detection is matched against active tracks using IoU. Two thresholds matter:

  • tracker_match_threshold — IoU below this means "no match" (1 − threshold = the IoU floor). Default 0.8 means IoU ≥ 0.2 matches. Lower values are STRICTER, not looser.
  • tracker_activation_threshold — minimum detection confidence to start a NEW track. Default 0.25.

Tracks survive brief occlusions via TRACKER_LOST_BUFFER (150 frames ≈ 5s @ 30fps, up from ByteTrack's default 30).

ByteTrack vs BoT-SORT — and the hybrid

ByteTrack associates purely by IoU and motion. BoT-SORT adds camera-motion compensation and (optionally) appearance re-identification, so it holds an identity through longer gaps and curved paths — but on dense, high-fps scenes it can over-extend a track and over-count. Neither wins everywhere, so the tracker is picked per camera by measurement.

In practice the two are combined into a hybrid, because throughs and turns have opposite needs:

MovementTrackerWhy
Throughs (the dominant volume)ByteTrack straight, fast, dense — IoU association is enough and doesn't over-extend
Turns (sparse, curved)BoT-SORT curved paths through occlusion need the stronger motion/appearance model to stay one track

apply_hybrid.py keeps the ByteTrack throughs and grafts in the BoT-SORT turns, gated by the path bank. cam1 goes a step further with full BoT-SORT + ReID. Which combination ships for a given camera is decided by the net-error measurement on page 7 — there is no global default.

Processing modes

Fast yolo26s 640 3 (every 3rd) 0.95 / 0.15 ~10–15× faster Previewing / iteration

Why Fast loosens the tracker thresholds

ByteTrack's Kalman filter assumes consecutive update() calls are one frame apart. With detection_skip=3 the tracker only sees every third frame, so its motion prediction under-shoots a moving vehicle by 3×. The next bbox can have ≈0 IoU with the predicted bbox.

Fast mode counters this by loosening the match threshold to 0.95 (IoU ≥ 0.05) and dropping the activation floor to 0.15 so single-detection fast vehicles can start a track rather than dying in the BYTE association queue.

Accurate & Balanced run detection on every frame, so their thresholds stay at strict ByteTrack defaults.
