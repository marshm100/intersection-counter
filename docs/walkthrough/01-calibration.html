1. Calibration

Before any video processing happens, a human engineer clicks on each approach leg in a still frame. Those clicks become origin points; the geometry derives everything else.

What gets calibrated, per camera

For each leg (3–4 per camera):

  • An origin point — single (x, y) on the approach.
  • A reference heading in degrees — the direction vehicles move when approaching. Computed from the origin point + the intersection center.
  • A cardinal direction label (NB / SB / EB / WB) and a friendly name (e.g. "SB N Belt Line Rd").

Heading convention

Image coordinates with y increasing downward. Heading is degrees clockwise from north: 0° = up, 90° = right, 180° = down, 270° = left.

From origin point to tripwire

The pipeline needs a line to test "did the vehicle's path cross it." Calibration only captures a single click point per leg. So at runtime we synthesize a tripwire by drawing a line through the origin point, perpendicular to the reference heading, extending TRIPWIRE_HALF_LENGTH_PX (currently 120) in each direction. 

line_start = origin - perp_unit * 120
line_end   = origin + perp_unit * 120
where  perp = ref_heading + 90°

Why a point and a heading aren't the whole story

Calibration captures the minimum a human can click reliably: one origin point and a heading per leg. That's enough to synthesize a tripwire and a fallback, but it has known limits — which is exactly why the current pipeline derives a richer geometry (the path bank) on top of it:

Vehicles are first detected past the tripwire. A leg's origin sits at the stop bar, but YOLO often first catches a vehicle already inside the intersection — past the line — so a pure tripwire-crossing test misses it. Matching the whole trajectory against a road shape (page 4) doesn't depend on catching the crossing moment.
The legs are not orthogonal. Reference headings here are 262° / 83° / 313° / 173° — no two legs exactly opposite. Anything assuming a clean four-way (a turn matrix, fixed 90° buckets) mislabels movements; classification adapts to the real geometry instead (page 5).
The cardinal label is load-bearing. The N/S/E/W direction isn't cosmetic — it's how each leg is joined to the Miovision ground-truth approach for validation. A mislabeled cardinal silently corrupts every count (it happened — see page 8).
