5. Movement Classification

With a track matched to the bank, its movement is already known — the path carries its own destination leg and label. This page covers that primary route, then the geometric fallback used when no path matches (or the camera has no bank).

Primary route: read it off the path

When the joint scorer (page 4) confidently matches a track to a bank path, classification is done: the path's destination_leg_id and movement_label are the answer. No separate destination scoring, no angle math. This is the case for the vast majority of tracks at a calibrated camera, and it's why the path bank is the heart of the pipeline — geometry learned once, reused for every vehicle. 

match = score_path_joint(trajectory, bank_paths)
if match.confident:
    destination_leg_id = match.path.destination_leg_id
    movement           = match.path.movement_label      # "left" / "through" / "right" / "u_turn"
else:
    # fall back to the geometric scorer below

Fallback: geometric destination scoring

When no path matches — a camera without a bank, or an unusual trajectory — the pipeline falls back to the v2 geometric scorer. First a quality gate, then a destination score.

Stage A — quality gate

Trajectories without enough motion to classify reliably are dropped rather than guessed:

num_points       < TRAJECTORY_MIN_POINTS (5)        → insufficient_data
total path dist  < TRAJECTORY_MIN_DISTANCE_PX (50)  → insufficient_data
tail moved       < EXIT_DISPLACEMENT_MIN_PX (20)    → no destination assigned

Stage B — destination-leg score

For each leg (including the origin, so U-turns are detectable), build an expected exit direction — the unit vector from the intersection center to that leg's origin — and score the track's exit velocity and exit position against it: 

for leg in all_legs:
    expected_dir   = unit(leg.origin - intersection_center)
    heading_score  = dot(exit_velocity,        expected_dir)
    position_score = dot(exit_pos_from_center, expected_dir)
    raw_score[leg] = 0.7 * heading_score + 0.3 * position_score

posterior       = softmax(raw_score, temperature=4.0)
destination_leg = argmax(posterior)

From (origin, destination) to a label

Either route ends with an origin and destination leg. derive_movement turns the pair into a label from reference-heading geometry — no fixed angle buckets, no turn matrix (a PRD constraint). Same leg = U-turn; otherwise the other legs are ranked by counter-clockwise delta from the origin and the rank gives the label:

Other-leg countRank 0Rank 1Rank 2
3 (four-leg)leftthroughright
2 (T-junction)leg within 60° of opposite = through; else both are turns
1 (degenerate)left if delta < 180°, else right
4+ (5-way)nearest-canonical (90 / 180 / 270)

Why not fixed angle buckets

A naive "delta ≤ 45° = through, 45–135 = turn, ≥135 = U-turn" rule assumes orthogonal roads. Real intersections aren't: camera 1's legs sit at 262° / 83° / 313° / 173° — no two exactly opposite. Fixed buckets mislabel real destinations there; the rank approach adapts to whatever geometry exists.

Where the bank earns its keep. The geometric fallback assumes the legs are peer roads — every leg can go through to its opposite, turn to its neighbors. That's false at terminating side streets and skewed junctions, and it produced phantom movements in the v2 data (a side street that physically can't go "through" still got through-labeled). The path bank fixes this structurally: it only contains the movements Miovision confirms exist, so a phantom through has no path to match. See Accuracy & Validation.

What gets written to the event

vehicle_events row:
  origin_leg_id         = 38
  destination_leg_id    = 39
  movement              = "right"
  trajectory_data       = "[[633,252],[610,244], ... ,[581,189]]"   # JSON
  trajectory_confidence = 0.74        # match confidence / softmax posterior
  classifier_*          = net_heading_change, path_distance, num_points, ...
  ...timestamps + vehicle class + bbox dims

The classifier_* columns are diagnostic — they let an analyst audit a misclassification, and let scripts re-score trajectories offline without re-running detection (the foundation of the replay harnesses on page 7).
