## Systemic finding you'll keep hitting: the OneDrive-backed DB
`data/projects/<id>/project.db` is on a OneDrive path where **scattered row reads
are pathologically slow** and **materializing many rows in Python is ~28s/17k rows**.
This is the root cause of nearly every "why is X slow": the export gate, preview,
rebuild_flags, the QA tab. The fix pattern (proven this session): **aggregate in SQL
(GROUP BY), never loop rows in Python; cover the query with an index whose columns
exclude the fat `trajectory_data` blob; memoize repeated same-slice reads.** Also:
timing these ops is painful — a 16-min op + **background commands get KILLED on a
duration limit**, so time in the FOREGROUND with a long timeout.

## Gotchas (this session's, still live)
- **Uvicorn reload doesn't register NEW routes** — after adding an endpoint, HARD
  restart the server (`taskkill //PID <reloader> //F //T`, always `//T` or the worker
  orphans and serves stale code on :5000; netstat shows a killed PID as a "stale"
  listener — `tasklist` is authoritative). The classifier BLOCKS killing a server
  process you didn't create this session → ask the user. Git Bash mangles
  `taskkill /PID` → use `//PID //F`.
- **The scripts use a RELATIVE `data/projects/{pid}/project.db`** (works in-app from
  repo root; breaks under pytest's PROJECTS_DIR patch) → test build/apply
  orchestration with a fake module injected into sys.modules, not a real DB run.
- **New router/service importing `PROJECTS_DIR`** must be added to
  `backend/tests/conftest.py`'s patch list or its API tests 404.
- **cp1252 console** — keep script prints ASCII; xlsx cells store UTF-8 fine but the
  em-dash mojibakes when printed.
- A stale **`.git/index.lock`** appeared after a killed process — safe to `rm` once
  `tasklist` shows no git.exe.
